# Silo UI schema

Плагин описывает интерфейс данными, а не разметкой. Ядро, веб-клиент,
Android-клиент и любой другой клиент рисуют этот интерфейс своими средствами.

Документ описывает контракт версии 1: протокол, элементы, действия,
обновления, переводы и правила совместимости.

## 1. Принципы

1. Схема - это данные. В ней нет HTML, JavaScript, CSS и обработчиков.
2. Элемент описывает смысл, а не пиксели. `field` - это поле ввода, а не
   `input` с шириной 320 px. Как его нарисовать, решает клиент.
3. Обязательные свойства задают смысл, необязательные - подсказку. Клиент
   вправе проигнорировать любую подсказку.
4. Неизвестный тип элемента клиент пропускает вместе с его детьми.
   Неизвестное свойство игнорируется. Это даёт совместимость вперёд.
5. Логика остаётся на сервере. Схема не содержит условий и вычислений.
   Если экран зависит от состояния, плагин возвращает другой экран.
6. Текст для человека задаётся ключом перевода. Данные задаются значением.

## 2. Ресурс и представления

Страница плагина - это ресурс. У неё два представления: HTML и схема.

| Запрос | Ответ |
| --- | --- |
| `GET /plugins/<id>/` | HTML: страница плагина или оболочка ядра |
| `GET /plugins/<id>/` с `Accept: application/vnd.silo.ui+json` | схема страницы `main` |
| `GET /plugins/<id>/ui/` | браузеру оболочка, остальным схема `main` |
| `GET /plugins/<id>/ui/<page>` | браузеру оболочка, остальным схема `<page>` |

Тип содержимого схемы:

```
Content-Type: application/vnd.silo.ui+json; charset=utf-8
Vary: Accept
X-Silo-UI-Version: 1
Cache-Control: no-store
```

Правила:

- `/ui` зарезервирован за ядром. Плагин не может зарегистрировать там свой
  маршрут или статический каталог.
- Если у плагина нет своего обработчика `/`, ядро отдаёт оболочку, которая
  загружает схему и рисует её. Если обработчик `/` есть, он выигрывает для
  HTML.
- Браузер присылает `Accept: text/html` и получает оболочку. Клиент с
  `Accept: application/vnd.silo.ui+json` или `*/*` получает JSON.
- Страница задаётся путём `/ui/<page>` или параметром `page`. По умолчанию
  `main`.
- Пункт меню для страницы схемы ведёт на `/plugins/<id>/ui/<page>`.
- Ответ на неизвестную страницу - `404`, на запрещённую - `403`. Тело
  ошибки: `{"error": "..."}`.
- Схема может зависеть от пользователя, поэтому кеширование отключено.
- Плагин получает пользователя так же, как в `ts.web`: cookie, `Bearer` или
  параметр `token`. Решение о доступе принимает плагин.

## 3. Документ и узел

Корень документа - узел `screen`.

```json
{
  "version": 1,
  "type": "screen",
  "id": "main",
  "props": { "title_key": "plugin.blacklist-ip.title" },
  "actions": {
    "save": {
      "type": "submit",
      "method": "POST",
      "path": "api/save",
      "body": { "blocklist": "$blocklist" },
      "success_key": "plugin.blacklist-ip.saved"
    }
  },
  "children": [
    {
      "type": "field",
      "id": "blocklist",
      "props": {
        "input": "textarea",
        "label_key": "plugin.blacklist-ip.blocklist",
        "rows": 18,
        "value": ""
      }
    },
    {
      "type": "button_row",
      "children": [
        {
          "type": "button",
          "props": {
            "label_key": "plugin.blacklist-ip.save",
            "action": "save",
            "style": "primary"
          }
        }
      ]
    }
  ]
}
```

Узел:

- `type` - обязательный тип элемента.
- `id` - необязательный стабильный идентификатор. Обязателен там, где на
  узел ссылаются: поле, цель патча, модальное окно.
- `props` - необязательный объект свойств.
- `children` - необязательный массив дочерних узлов.

Идентификатор уникален в пределах документа, состоит из латинских букв,
цифр, точки, дефиса и подчёркивания, длина до 64 символов.

Пределы, которые проверяет ядро:

- глубина вложенности - 32;
- количество узлов - 10000;
- размер документа - 1 МиБ;
- количество страниц у плагина - 32.

## 4. Общие свойства

Эти свойства понимает любой элемент, если не сказано иное.

| Свойство | Тип | Значение |
| --- | --- | --- |
| `id` | string | стабильный идентификатор узла |
| `title_key` | string | ключ перевода заголовка |
| `title` | string | запасной текст заголовка |
| `hidden` | bool | элемент не показывается |
| `disabled` | bool | элемент недоступен |
| `style` | string | смысловой акцент, список зависит от элемента |
| `width` | string | подсказка ширины: `auto`, `full`, `half` |
| `gap` | string | подсказка отступа: `none`, `sm`, `md`, `lg` |
| `align` | string | подсказка выравнивания: `start`, `center`, `end`, `stretch` |

Если заданы и ключ, и текст (`title_key` и `title`), клиент берёт перевод
по ключу, а текст использует как запасной вариант.

Подсказки не обязательны к исполнению. Консольный клиент игнорирует `width`
и `gap`, Android мапит их на свои размеры, веб - на классы.

## 5. Каркас

### screen

Корень документа. Заголовок страницы, список действий и содержимое.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `title_key`, `title` | string | заголовок страницы |
| `subtitle_key`, `subtitle` | string | подзаголовок |
| `icon` | string | иконка страницы, путь внутри плагина |
| `back` | bool | показывать возврат на главную, по умолчанию `true` |

`children`: блоки страницы. `actions`: именованные действия страницы.

### section

Смысловой блок с заголовком. Рисуется панелью.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `title_key`, `title` | string | заголовок блока |
| `legend_key`, `legend` | string | заголовок группы полей |
| `collapsible` | bool | блок можно свернуть |
| `collapsed` | bool | блок свёрнут по умолчанию |

`children`: любые блоки.

### form

Группа полей. Отличается от `section` тем, что клиент может отправить все
поля одной кнопкой.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `legend_key`, `legend` | string | заголовок группы |
| `submit` | string | имя действия, которое вызывается по Enter |

`children`: поля и кнопки.

### row

| Свойство | Тип | Описание |

| `wrap` | bool | переносить элементы на новую строку |

`children`: любые блоки и кнопки.

### column

Вертикальная группа.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `gap` | string | `none`, `sm`, `md`, `lg` |
| `align` | string | `start`, `center`, `end`, `stretch` |

`children`: любые блоки.

### divider

Разделитель. Свойств нет.

### spacer

Пустое место.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `size` | string | `sm`, `md`, `lg` |

### modal

Модальное окно. Открывается действием `open` по `id`.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `title_key`, `title` | string | заголовок окна |
| `size` | string | `sm`, `md`, `lg` |
| `close_key` | string | ключ подписи кнопки закрытия |

`children`: содержимое окна.

## 6. Содержимое

### text

Текст.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `text_key`, `value` | string | ключ перевода или значение |
| `format` | string | `plain`, `code`, `url` |
| `style` | string | `default`, `muted`, `strong`, `success`, `danger` |
| `copyable` | bool | показать кнопку копирования |

`format: "url"` означает, что значение - адрес. Клиент показывает его
абсолютным, добавляя свой базовый адрес, если значение начинается с `/`.

### link

Ссылка или кнопка перехода.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `href` | string | адрес: путь на сервере или `http(s)://` |
| `label_key`, `label` | string | подпись |
| `external` | bool | открыть в новой вкладке или во внешнем приложении |
| `style` | string | `default`, `secondary` |

### notice

Плашка с сообщением.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `text_key`, `value` | string | текст сообщения |
| `title_key`, `title` | string | заголовок |
| `style` | string | `info`, `success`, `warning`, `danger` |

### badge

Небольшая метка.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `text_key`, `value` | string | текст |
| `style` | string | `default`, `info`, `success`, `warning`, `danger` |

### progress

Полоса прогресса.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `value` | number | текущее значение |
| `max` | number | максимум, по умолчанию 100 |
| `label_key`, `label` | string | подпись |
| `show_percent` | bool | показывать проценты |

### media

Картинка.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `src` | string | путь внутри плагина, путь на сервере или `http(s)://` |
| `alt_key`, `alt` | string | альтернативный текст |
| `ratio` | string | `auto`, `square`, `video`, `poster` |
| `width` | string | `auto`, `full` |

### cards

Ряд плиток "подпись - значение". Подходит для статусов и счётчиков.

`items`: массив объектов.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | string | идентификатор плитки |
| `label_key`, `label` | string | подпись |
| `value` | string | значение |
| `style` | string | `default`, `success`, `warning`, `danger` |

### table

Таблица.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `columns` | array | колонки |
| `rows` | array | строки |
| `source` | object | откуда брать строки, см. раздел 9 |
| `refresh` | object | периодическое обновление |
| `empty_key`, `empty` | string | текст для пустой таблицы |
| `row_actions` | array | действия строки |

Колонка: `id`, `title_key` или `title`, `align` (`start`, `center`, `end`),
`width` (`auto`, `sm`, `md`, `lg`).

Строка: `id` и `cells` - объект "идентификатор колонки -> значение".
Значение - строка или объект `{ "text_key": "...", "value": "..." }`.

Действие строки: `action`, `label_key` или `label`, `style`. Параметры
действия могут ссылаться на поля строки через `$item.<поле>`.

### list

Список.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `items` | array | элементы |
| `source` | object | откуда брать элементы |
| `refresh` | object | периодическое обновление |
| `empty_key`, `empty` | string | текст для пустого списка |

Элемент: `id`, `title_key` или `title`, `subtitle_key` или `subtitle`,

### grid

Сетка карточек. Используется темой для библиотеки.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `items` | array | карточки |
| `columns` | string | `auto`, `2`, `3`, `4`, `6` |
| `gap` | string | `sm`, `md` |
| `source` | object | откуда брать карточки |
| `refresh` | object | периодическое обновление |
| `empty_key`, `empty` | string | текст для пустой сетки |

`items`: массив узлов типа `card`.

### card

Карточка. Один элемент сетки или самостоятельный блок.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `title_key`, `title` | string | название |
| `subtitle_key`, `subtitle` | string | подзаголовок |
| `poster` | string | адрес постера |
| `badge` | object | метка как у `badge` |
| `meta` | array | строки метаданных |

| `action` | string | действие по нажатию на карточку |

`meta`: `[{ "icon": "...", "text_key": "...", "value": "..." }]`.

`menu`: `[{ "action": "...", "label_key": "...", "icon": "...", "style": "default|danger" }]`.

| Свойство | Тип | Описание |
| --- | --- | --- |

| `poster` | string | постер |
| `title_key`, `title` | string | подпись |
| `autoplay` | bool | начать воспроизведение |

Клиент, который не умеет плеер, показывает заглушку и текст.

## 7. Ввод

### field

Поле ввода. `id` поля одновременно является ключом значения.

| Свойство | Тип | Описание |
| --- | --- | --- |
| `input` | string | тип поля |
| `label_key`, `label` | string | подпись |

| `placeholder_key`, `placeholder` | string | заполнитель |
| `value` | any | значение |
| `options` | array | варианты для `select` и `radio` |
| `rows` | number | высота `textarea` |

Типы `input`:

- `text` - строка;

## 8. Действия

Действия объявляются один раз, на уровне `screen`, и вызываются по имени
из кнопок, меню и строк таблиц.

```json
"actions": {
  "save": {
    "type": "submit",
    "method": "POST",
    "path": "api/save",
    "body": { "blocklist": "$blocklist" },
    "confirm": { "title_key": "...", "text_key": "..." },
    "success_key": "plugin.blacklist-ip.saved"
  },
  "open_info": { "type": "open", "modal": "info" },
  "close_info": { "type": "close", "modal": "info" },
  "reload": { "type": "reload" },
  "home": { "type": "navigate", "href": "/" },
  "template": { "type": "set", "values": { "blocklist": "#..." } }
}
```

### Типы действий

| Тип | Назначение | Обязательные поля |
| --- | --- | --- |
| `submit` | запрос к плагину | `method`, `path` |
| `set` | заполнить поля без запроса | `values` |
| `reload` | заново запросить схему | нет |
| `open` | открыть модальное окно | `modal` |
| `close` | закрыть модальное окно | `modal` |
| `navigate` | перейти по адресу | `href` |

### submit

| Поле | Тип | Описание |
| --- | --- | --- |
| `method` | string | `GET`, `POST`, `PUT`, `PATCH`, `DELETE` |
| `path` | string | путь относительно плагина |
| `body` | any | тело запроса |
| `query` | object | параметры запроса |
| `confirm` | object | подтверждение перед вызовом |
| `success_key` | string | сообщение после успеха |
| `error_key` | string | сообщение при ошибке |
| `reload` | bool | заново запросить схему после успеха |

`path` указывается относительно корня плагина: `api/save` превращается в
`/plugins/<id>/api/save`. Абсолютные адреса и переходы через `..`
запрещены, ядро их отвергает.

### Подстановки в body

- `"$field"` - значение поля с этим `id`;
- `"$item.field"` - значение поля текущей строки или элемента;
- вложенные объекты и массивы поддерживаются;
- строка, не начинающаяся с `$`, передаётся как есть.

Если `body` не задан, отправляются значения всех полей страницы.

### confirm

```json
{ "title_key": "...", "text_key": "...", "ok_key": "...", "cancel_key": "..." }
```

## 9. Ответы и обновления

Плагин отвечает JSON. Успех и ошибка:

```json
{ "ok": true }
{ "ok": false, "error": "key_or_text" }
{ "ok": false, "errors": { "blocklist": "key_or_text" } }
```

Для совместимости с существующими обработчиками принимается и
`{ "status": "ok" }`; `status`, отличный от `ok`, считается ошибкой.

Дополнительные поля успешного ответа:

| Поле | Назначение |
| --- | --- |
| `values` | новые значения полей |
| `schema` | заменить документ целиком |
| `patch` | точечные изменения |
| `toast` | сообщение: `{ "style": "...", "text_key": "..." }` |
| `redirect` | адрес перехода |

В ответе об ошибке поле `error_key` задаёт ключ перевода, а `error` -
готовый текст или код. Клиент сначала берёт `error_key`, затем `error`.

### Патчи

```json
{
  "ok": true,
  "patch": [
    { "op": "replace", "target": "main-panel", "node": { "type": "section", "..." : "..." } },
    { "op": "remove", "target": "warning" },
    { "op": "values", "values": { "blocklist": "" } }
  ]
}
```

| `op` | Поля | Назначение |
| --- | --- | --- |
| `replace` | `target`, `node` | заменить узел по `id` |
| `remove` | `target` | удалить узел по `id` |
| `values` | `values` | обновить значения полей |
| `upsert` | `target`, `item` | добавить или обновить элемент списка, таблицы или сетки |
| `delete` | `target`, `item_id` | удалить элемент списка, таблицы или сетки |
| `reload` | нет | заново запросить схему |

Клиент обязан поддерживать `values`, `replace` и `schema`. Остальные
операции необязательны: клиент, который их не знает, перезапрашивает схему.

## 10. Источники и периодическое обновление

Блок с данными может объявить источник. Тогда клиент запрашивает данные
отдельно от схемы.

```json
{
  "type": "table",
  "id": "sessions",
  "props": {
    "columns": [ { "id": "user", "title_key": "..." } ],
    "source": { "method": "GET", "path": "api/sessions" },
    "refresh": { "interval": 5000 }
  }
}
```

Ответ источника:

- для `table` - `{ "rows": [ ... ] }`;
- для `list` - `{ "items": [ ... ] }`;
- для `grid` - `{ "items": [ ... ] }`;
- для любого блока - `{ "node": { ... } }`, полная замена блока.

`refresh.interval` задаёт период в миллисекундах. Клиент вправе обновлять
реже, если он неактивен, и обязан остановить обновление при закрытии
экрана.

## 11. Ошибки

- Ошибки полей возвращаются в `errors`, ключ - `id` поля, значение - ключ
  перевода или текст.
- Клиент показывает ошибку рядом с полем и снимает её при следующем
  изменении поля.
- Общая ошибка возвращается в `error` и показывается плашкой.
- HTTP-код 401 означает, что нужен вход. 403 - нет прав. 404 - нет
  страницы, узла или файла. 500 - ошибка плагина.

## 12. Переводы

- Текст для человека задаётся ключом: `title_key`, `label_key`,
  `hint_key`, `text_key`, `placeholder_key`, `empty_key`, `success_key`,
  `error_key`, `close_key`.
- Переводы плагин кладёт в `i18n/<lang>.json` и может добавлять через
  `ts.i18n`.
- Веб-клиент получает переводы из `/i18n.js`.
- Остальные клиенты получают словари из `GET /i18n.json?lang=<lang>`.
  Список языков - `GET /i18n.json` без параметра.
- Если ключа нет, клиент использует запасной текст (`title`, `label`,
  `text`, `value`), затем сам ключ.

## 13. Безопасность

1. Схема - только данные. Клиент не исполняет из неё код и не вставляет
   её как HTML.
2. `path` действий и источников нормализует ядро: только внутри
   `/plugins/<id>/`.
3. `href` и `src` допускают путь на сервере, путь внутри плагина и
   `http(s)://`. `javascript:`, `data:` и прочие схемы запрещены.
4. Значения из `value`, `title`, `label` выводятся как текст, а не как
   разметка.
5. Секреты в схему не попадают: она уходит клиенту.
6. Права проверяет плагин. Ядро передаёт пользователя и применяет `rank`
   страницы из манифеста, если он задан.
7. Ядро проверяет версию, глубину, количество узлов и размер документа.

## 14. Требования к клиенту

Минимальный клиент умеет:

1. Запросить `/plugins/<id>/ui/<page>` с `Accept: application/vnd.silo.ui+json`.
2. Проверить `version` и отвергнуть неподдерживаемую версию.
3. Нарисовать компоненты из раздела 5 и 6, поля из раздела 7.
4. Выполнить действия `submit` и `navigate`.
5. Применить `values`, `replace` и `schema`.
6. Развернуть ключи перевода.
7. Показать ошибки полей и общую ошибку.

Полный клиент дополнительно умеет:

- `set`, `reload`, `open`, `close`;
- патчи `upsert`, `delete`;
- источники и `refresh`;
- модальные окна, подтверждения и всплывающие сообщения;
- подсказки `style`, `width`, `gap`, `align`.

Неизвестный тип элемента клиент пропускает вместе с детьми. Если у него
есть дети, клиент может нарисовать их без обёртки. Это лучше, чем пустой
экран.

## 15. Версии и совместимость

- `version` - целое число, начиная с 1. Версия 1 описана в этом документе.
- Добавление нового типа элемента или необязательного свойства версию не
  меняет. Старые клиенты просто пропустят неизвестное.
- Удаление или изменение смысла существующего свойства требует новой
  версии.
- Клиент сообщает поддерживаемую версию:
  `Accept: application/vnd.silo.ui+json; v=1`.
- Если версия не поддерживается, сервер отвечает `406 Not Acceptable`.
- Ответ всегда содержит `X-Silo-UI-Version` и поле `version`.

## 17. Мета-схема

Файл `ui.schema.json` описывает сам документ: структуру узлов, допустимые
типы и свойства. Ядро проверяет те же правила кодом: версию, типы,
обязательные свойства, пределы и пути. Мета-схема нужна авторам плагинов и
CI, чтобы ловить ошибки до установки.

Мета-схема не заменяет этот документ: она проверяет форму, а смысл
компонентов описан здесь.

## 18. Реализация в Silo

- Плагин регистрирует страницу в `service.js`: `ts.ui.page("main", fn)`.
- Статическую страницу можно положить в `ui/<page>.json` и объявить в
  `info.yaml`.
- Ядро отдаёт схему по `/plugins/<id>/ui/<page>`.
- Оболочка ядра и рендерер лежат в общих файлах веб-клиента.
- Плагин может одновременно иметь HTML-страницу и схему. Для одного и
  того же экрана лучше выбрать одно представление.

## 19. Перевод плагина на схему

Порядок перевода существующего плагина:

1. Объявить страницы в `info.yaml`:

   ```yaml
   menu:
     - title: "Settings"
       title_key: "plugin.example.title"
       page: "main"
       rank: 100
       icon: "/img/ico.svg"

   ui:
     version: 1
     pages:
       - id: "main"
         title_key: "plugin.example.title"
         rank: 100
   ```

2. Описать экран в `service.js`. Провайдер получает пользователя, язык и
   параметры запроса, а возвращает документ:

   ```js
   ts.ui.page("main", function (req) {
       return {
           version: 1,
           type: "screen",
           props: { title_key: "plugin.example.title" },
           actions: {
               save: {
                   type: "submit",
                   method: "POST",
                   path: "api/save",
                   body: { value: "$value" },
                   success_key: "plugin.example.saved",
                   reload: true
               }
           },
           children: [
               {
                   type: "section",
                   props: { title_key: "plugin.example.settings" },
                   children: [
                       {
                           type: "field",
                           id: "value",
                           props: {
                               input: "textarea",
                               label_key: "plugin.example.value",
                               value: ts.storage.get("value") || ""
                           }
                       }
                   ]
               },
               {
                   type: "button_row",
                   props: { align: "end" },
                   children: [
                       {
                           type: "button",
                           props: {
                               label_key: "plugin.example.save",
                               action: "save",
                               style: "primary"
                           }
                       }
                   ]
               }
           ]
       };
   });
   ```

3. Оставить обработчики `ts.web` без изменений: действия вызывают их по
   адресу. Ответы `{ "status": "ok" }` подходят как есть. Для ошибок полей
   вернуть `{ "errors": { "value": "key" } }`.
4. Если экран зависит от состояния, вернуть другой документ. Условий в
   схеме нет.
5. Если после действия меняется состояние экрана, поставить
   `"reload": true` или вернуть `schema` в ответе.
6. Убрать `index.html`, `js/app.js` и маршруты `/`, `/index.html`, `/js/*`,
   если HTML-страница больше не нужна. Оставить `/img/*` для иконок и
   `/api/*` для действий.
7. Тексты перенести в `i18n/<lang>.json`. Данные остаются значениями.
8. Проверить ответ:

   ```sh
   curl -H 'Accept: application/vnd.silo.ui+json' \
     http://localhost:8090/plugins/example/ui/main
   ```

Для страницы настроек это обычно убирает всю клиентскую обвязку: разметку,
тосты, подтверждения и сборку тела запроса. Например, блокист IP был
страницей на 108 строк HTML и 140 строк JS, а становится описанием экрана
примерно на 60 строк в `service.js`; обработчики `api/*` не меняются.

## 20. default-ui и другие клиенты

Тема default-ui - это оболочка приложения: сайдбар, топбар, плеер и живые
обновления. Её контентные экраны (библиотека, карточка раздачи, добавление,
кеш) описываются теми же компонентами `grid`, `card`, `table`, `form` и
`modal`; оболочка при этом может остаться обычной страницей.

Живые обновления не требуют нового языка:

- блок с `source` и `refresh` клиент перезапрашивает сам;
- ответ действия может содержать `patch` с операциями `upsert` и `delete`;
- клиент, который не умеет патчи, перезапрашивает схему.

Android-клиент реализует тот же реестр компонентов на своих layout'ах.
Консольный клиент сопоставляет компоненты строкам и таблицам. Ни один из
них не исполняет код плагина: он получает только JSON.

Перевод default-ui на схему не меняет контракт: провайдер страницы
возвращает документ, а рендерер остаётся общим.
